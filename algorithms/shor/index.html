Factoring and order finding

Motivation and intuition¶

Factoring an integer becomes easier if we know the period of its modular powers. Shor’s algorithm uses interference to reveal that period: a superposition of exponents is entangled with ax mod Na^x\bmod NaxmodN, and an inverse Fourier transform makes samples concentrate near multiples of the reciprocal order Shor, 1997. The classical gcd step turns suitable periods into factors. The survey discusses the application and its full resource context Dalzell et al., 2025.

Implementation status

The N=15N=15N=15 and N=21N=21N=21 examples execute actual modular-add and modular-multiply circuits, with numerical checks against independent classical answers. The parameterized generator constructs gates without an arithmetic lookup table or a dense unitary matrix. Logical scaling is measured separately from the bounded simulations. The default Fourier projection is joined by eight matched Fourier/ripple surface-code reports for four-, five-, and six-bit workloads. These use the audited QDK mean synthesis-cost model; they do not supply certified Clifford+T approximations or a general factoring benchmark. The measured-AND companion adds an executed ideal measurement-assisted replacement, bounded addition/order checks and materialized logical scaling; its physical comparison and mechanized proof remain pending.

Task, input and intuition¶

Given NNN and a chosen base aaa with gcd⁡(a,N)=1\gcd(a,N)=1gcd(a,N)=1, the order is the smallest positive rrr satisfying ar≡1(modN)a^r\equiv1\pmod Nar≡1(modN). If a verified period is even, let b=ar/2 mod Nb=a^{r/2}\bmod Nb=ar/2modN. Nontrivial values of gcd⁡(b−1,N)\gcd(b-1,N)gcd(b−1,N) and gcd⁡(b+1,N)\gcd(b+1,N)gcd(b+1,N) give factors. Odd periods and b=±1b=\pm1b=±1 can fail, so they must not disappear from success accounting.

Our input is the classical pair (N,a)(N,a)(N,a). It specifies ordinary gate constants and the bit width n=⌈log⁡2N⌉n=\lceil\log_2N\rceiln=⌈log2​N⌉; there is no external database or amplitude-loading oracle. The work register begins at 1, while the ttt exponent qubits begin in a uniform superposition. Controlled multiplication by a2j mod Na^{2^j}\bmod Na2jmodN entangles the jjjth exponent bit with the modular-power register. All work ancillas are uncomputed before the inverse QFT and exponent readout.

Fundamental algorithm and real arithmetic¶

The arithmetic follows Fourier addition and compute–swap–uncompute multiplication Draper, 2000Beauregard, 2003, using an original Qiskit 2.6.2 implementation. Qiskit is Apache-2.0 software; see its upstream repository and our MIT implementation.

For 0≤y<N0\le y<N0≤y<N, a modular addition uses an (n+1)(n+1)(n+1)-bit accumulator and one borrow flag. In the Fourier basis it adds a constant ccc, subtracts NNN, conditionally restores NNN after inspecting the high bit, and removes the borrow information using the relation between the result and ccc. QFTs, controlled phase gates, X gates and CX gates implement every step. Addition by ccc is controlled; the subtract/restore work cancels on inactive control branches. The accumulator’s high bit and borrow flag return to zero.

To multiply by aaa, add a2j mod Na2^j\bmod Na2jmodN into a zero accumulator, controlled by each input bit. Swap the input with the result under the exponent control. Then subtract the binary-weighted multiples of a−1 mod Na^{-1}\bmod Na−1modN controlled by the new input bits. The old input is erased because a−1(ax mod N)≡x(modN)a^{-1}(ax\bmod N)\equiv x\pmod Na−1(axmodN)≡x(modN). This includes the inverse arithmetic, rather than charging an opaque modular-multiplication box.

The contract requires x<Nx<Nx<N, a zero accumulator and a clean flag. Outside that subspace the same gate circuit remains reversible, but we assign it no modular-arithmetic meaning. All QFT angles are numerical representations of exact analytic angles; fault-tolerant synthesis is a separate layer.

In-memory arithmetic preserves the relative phases needed for coherent controls. The pinned QASM exporter omits the compiled circuit’s overall global phase, recorded in the ledger. Our QASM files describe complete measured trials with unchanged probabilities; they are not specifications for a phase-preserving oracle to be coherently controlled again.

We should name the complete construction being compared: an optimized Shor order finder, an Ekerå–Håstad short-discrete-logarithm reduction for RSA moduli, and Regev’s factoring algorithm have different input and success contracts. The existing N15/N21 generators remain the implemented baseline.

Regev-style factoring is a separate algorithm family¶

Regev’s published algorithm uses approximately n\sqrt nn​ independent quantum executions, each with a gate count of order n3/2n^{3/2}n3/2 up to logarithmic factors, followed by classical lattice processing. Its correctness relies on a number-theoretic conjecture, and the paper explicitly leaves practical physical improvement unresolved Regev, 2025. The gate count is per execution: the repetitions and classical lattice work must remain in the total cost.

Ragavan and Vaikuntanathan reduce the quantum workspace while keeping the smaller per-run circuit and make classical recovery tolerate a constant fraction of corrupted runs Ragavan & Vaikuntanathan, 2026. The inspected associated manuscript states O(nlog⁡n)O(n\log n)O(nlogn) qubits and O(n3/2log⁡n)O(n^{3/2}\log n)O(n3/2logn) gates per run, with O(n)O(\sqrt n)O(n​) runs. These asymptotic statements use the papers’ arithmetic model, rather than the current book generator’s simple cubic arithmetic. Tolerance of corrupted samples is a recovery property; a physical implementation still needs error correction, synthesis and a failure budget.

This deserves a separate planned page beneath the factoring chapter when we implement it. That page should show a small multidimensional exponentiation circuit, actual lattice recovery, the number-theoretic assumption, and a comparison with the same factoring/output/success task. No Regev circuit or physical estimate is implemented here yet.

External end-to-end resource references¶

The Gidney–Ekerå construction is a useful external end-to-end reference: it combines optimized arithmetic and recovery with a surface-code layout, magic-state factories, repeated attempts and a specified controller reaction time Gidney & Ekerå, 2021. Its RSA-2048 estimate uses 20 million noisy qubits and an expected eight-hour runtime under a particular nearest-neighbor hardware model. Those numbers are not extrapolations from our N15/N21 circuits.

A later Gidney preprint trades more time for less space, using approximate residue arithmetic, dense idle storage and smaller magic-state production. Its headline estimate is below a million noisy qubits and below a week, with the same stated physical error, cycle and controller assumptions as the earlier reference Gidney, 2025. The paper’s dense-storage choice uses yoked surface codes, whose published memory results concern a hierarchical code over a nearest-neighbor square grid Gidney et al., 2025. A lower memory cost is not automatically a faster complete algorithm: transfers between storage and computation, factory throughput, arithmetic retries and controller latency still matter.

We will treat these as external conditional resource models, not as validated improvements to this book’s frozen baseline. A matched co-design comparison must hold the factoring problem, accepted input class, output, total failure probability and hardware assumptions fixed, and report physical qubits, runtime and spacetime volume. A new code or memory architecture also needs its own noise, operation and scheduling model.

The 2025 paper’s Zenodo code-and-assets record is an exact upstream starting point. The inspected record has a 6,220,929-byte code.zip and a CC-BY-4.0 license. We have inspected the record metadata, not executed that archive. The 2021 arXiv source separately provides estimate_costs.py and related ancillary files.

The November 2026 shared-lookup preprint provides a further arithmetic candidate and an exact supporting archive, whose metadata declares CC-BY-4.0 Sharma & Lau, 2026. We inspected the manuscript and archive metadata, not the archive’s executable source. Its comparisons bind logical-qubit budgets and reference-simulator counts; wider shared lookup words can change the runtime benefit on another architecture. Neither its gate reductions nor its conditional timing transfers are a reproduced improvement to our frozen factoring workload.

Verification and formalization¶

The dedicated tests check positive-exponent QFT matrices, modular addition over valid basis inputs and active/inactive controls, multiplier semantics, auxiliary cleanup, coherent relative phases and decomposition. Full N=15N=15N=15 and N=21N=21N=21 phase marginals are compared with an independently evaluated Fourier sum over residue classes. This tests the actual circuit, rather than constructing a reference arithmetic matrix and calling it an implementation.

An independent review additionally checked 1,743 modular-adder branches and 102 multiplier branches through N=21N=21N=21, with full complex-amplitude discrepancies below 4×10−144\times10^{-14}4×10−14. Numerical tests cover the stated bounded inputs; they are not a proof for every width.

Checks for the physical scaling study¶

The scaling study derives ideal probabilities from independent FFTs of classical modular-power residue indicators and compares them with the geometric Fourier reference. The actual continued-fraction, modular-period verification and gcd rule defines factor success. The independent order reference is evaluated after circuit materialization and never supplies gate constants or chooses phase precision.

Every distinct ripple power multiplier is checked on all valid input/control branches with clean work restoration. Independent review checks the corresponding Fourier powers on coherent superpositions over the valid domain. Tiny actual full circuits and controlled multipliers are compared with independent classical and complex-amplitude answers. Bounded sparse simulation also rechecks the N15/t8 and N21/t6 ripple circuits. The larger N21/t10 and N35/t12 materializations have arithmetic and resource checks; no fresh full-state simulation or formal proof is claimed for them. Exported QASM, native-input hashes, readout mappings, complete retry counts and model allocations are checked separately.

Kernel-compiled finite two-bit adder reference¶

Available external formalization¶

Full-generator formal correspondence remains pending. The finite reference above has its own narrower source and foundation inventory.

Formalization is available at several layers. Peng and colleagues published an end-to-end ideal Shor development in Coq, including returned-factor correctness and a repeated-trial failure bound Peng et al., 2023. The inspected SQIR source contains the theorems end_to_end_shors_correct and end_to_end_shors_fails_with_low_probability, extraction-oriented circuit correspondence, and logical gate-count results. Coq/Rocq and Lean are different proof assistants. The upstream extraction route explicitly retains assumptions about OCaml floats, Zarith arithmetic, the measurement simulator and handwritten I/O.

A 2026 Lean preprint is a concrete additional reference Zhang et al., 2026. The inspected Lean-QuantumAlg source exposes separate declared-oracle Shor, measured-arithmetic RSA logical models and fixed RSA-2048 endpoints. The declared-oracle model’s oracle coordinate is not a compiled modular-arithmetic gate count. The RSA endpoint is an Ekerå–Håstad-style model with explicit accepted-key and success assumptions; its logical resource ceilings use exact arbitrary one-qubit semantics and supply neither a Clifford+T approximation certificate nor physical surface-code runtimes. The P-256 construction concerns elliptic-curve discrete logarithms rather than integer factoring.

These are inspected external references, not reproduced or integrated proofs. The Lean paper is an unreviewed preprint, and the inspected October source is later than its July manuscript. A proof-reproduction artifact must pin a source commit, dependencies, exact theorem and complete assumption inventory, then record a successful kernel build. Verifying this book’s implementation additionally requires a correspondence between our arithmetic/export/lowering and the proved model. A linked repository does not establish that correspondence.

The inspected Lean source is Apache-2.0; its lean-toolchain requires Lean 4.33.1 and its Lake manifest resolves mathlib 4.33.1 to an exact commit. Reproduce, change the input and download¶

Use Python 3.12 and the locked environment, or install the downloadable code package. The notebook reuses the same source and offers editable bounded parameters in a live local or Binder kernel. The static website needs no kernel backend.

python scripts/generate_shor.py --physical
pytest tests/test_shor.py
python scripts/generate_shor.py --modulus 33 --base 2 --phase-bits 12 \
  --no-sim --no-scaling --output-dir artifacts/shor-33

The generator permits at most 12 input bits and 24 exponent bits, subject to a conservative arithmetic-work preflight and a 500,000 expanded-operation cap. Statevector execution is separately capped at 18 total wires. The guard does not promise efficient simulation or compilation of every accepted input. Exact statevector memory grows as 2Q2^Q2Q; large arithmetic simulations need a different recorded computation job.

python scripts/generate_shor_scaling.py

  --output-dir artifacts/shor-33-base5
