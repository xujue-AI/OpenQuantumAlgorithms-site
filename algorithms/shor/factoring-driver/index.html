A complete bounded factoring driver

A successful fixed-base order measurement is only one part of factoring. A driver must also recognize easy classical cases, choose bases, retain failed measurements, verify proposed factors and stop honestly when its budget is spent. This page implements that full control flow for bounded inputs, using the actual modular arithmetic from the main chapter.

Status and output contract

The driver returns a verified nontrivial factor split, an exact bounded prime classification, or an explicit failure/resource limit. A recursive wrapper continues splits until all factors are prime or some components remain unresolved. The circuits and traces below are executed ideal simulations; no generic factoring confidence theorem or adaptive fault-tolerant projection is supplied.

Classical preparation and random bases¶

All inputs are integers 2≤N≤40952\le N\le40952≤N≤4095. The driver checks small primes, even inputs and exact perfect powers using integer roots. It then uses a deterministic two-base Miller–Rabin implementation in this bounded domain. The dedicated tests compare every input in the domain against an independent sieve; this is not an unbounded primality claim. Strong-pseudoprime tests provide the broader context Jaeschke, 1993.

For an odd composite that survives these checks, bases are drawn uniformly with replacement from 2,…,N−12,\ldots,N-12,…,N−1 using a recorded NumPy seed. A nontrivial gcd⁡(a,N)\gcd(a,N)gcd(a,N) is an immediate classical factor. Coprime bases receive a bounded number of complete quantum trials. Every outcome is processed by continued fractions, checked with ad mod Na^d\bmod NadmodN, and followed by gcd factor verification. The driver never enumerates the order to construct a circuit, sample a result or decide when to stop.

Recycled-control phase estimation¶

The semiclassical inverse Fourier transform replaces the exponent register with one measured and recycled control qubit Griffiths & Niu, 1996. Our original Qiskit 2.6.2 implementation uses actual reset, measurement and classical if_test operations. Qiskit is Apache-2.0 software; upstream is credited separately from our MIT code.

Whole-policy success and scaling¶

Let BBB be the maximum base draws, SSS the trials allowed per coprime base and KKK the global quantum-trial cap. The driver follows all three caps, including cases where K<BSK<BSK<BS. We provide a separate numerical ideal-policy audit for N≤63N\le63N≤63 using an independent reference distribution; the actual driver does not call that reference.

For bbb remaining bases and qqq remaining quantum trials, the audit averages failures over all coprime bases. A noncoprime base contributes zero failure. For a coprime base with ideal success pap_apa​, use u=min⁡(S,q)u=\min(S,q)u=min(S,q) trials; its failure contribution is (1−pa)u(1-p_a)^u(1−pa​)u times continuation F(b−1,q−S)F(b-1,q-S)F(b−1,q−S) when q≥Sq\ge Sq≥S, or a terminal failure when q<Sq<Sq<S. Also F(0,q)=1F(0,q)=1F(0,q)=1. A cap reached between bases still permits the next base’s classical gcd check; a cap reached inside a base terminates that run. This distinction is tested against independent finite-policy enumeration.

For example, N=15,t≥4N=15,t\ge4N=15,t≥4 has six immediately successful noncoprime bases, six coprime bases with pa=1/2p_a=1/2pa​=1/2, and base 14 with zero factor probability. An uncensored B=8,S=2,K=16B=8,S=2,K=16B=8,S=2,K=16 policy has modeled ideal failure (5/26)8(5/26)^8(5/26)8. The calculation is numerical and conditional on independent fresh trials, exact arithmetic/angles and the declared base policy; it is not a synthesis, physical-fault or generic algorithm-confidence certificate.

Recycled-control width is 2n+32n+32n+3, instead of t+2n+2t+2n+2t+2n+2 for the full exponent register. Each trial retains O(tn3+t2)O(tn^3+t^2)O(tn3+t2) logical work with the exact Fourier arithmetic, plus ttt measurements and 2n+t+22n+t+22n+t+2 resets. A run with R≤KR\le KR≤K completed trials charges every complete path; classical base selection, integer-root tests, modular exponentiation and gcd processing use integer arithmetic and are timed separately. The recursive wrapper permits at most 2n−12n-12n−1 component calls, within its explicit domain cap. Seeded successful examples establish neither a quantum advantage nor a general runtime bound.

Fault-tolerant analysis and verification¶

The main chapter’s surface-code report models a different, fixed full-register circuit. It cannot be reused as this driver’s physical estimate. The current shared QDK adapter rejects resets and intermediate/classically controlled measurements; omitting them would remove work required by the implementation. A complete adaptive estimate still needs initialization/reset error and timing models, measurement-conditioned schedules, classical feedback latency, approximation budgets and faults across all possible trials. Physical resources are therefore pending, while the recorded logical ledger is executed and complete for each observed ideal path.

Thirty-two dedicated tests cover the full bounded primality domain, exact roots, actual adaptive versus full-register circuit distributions, cap transitions, failed work, random-base success and recursive product invariants. Independent review additionally checked 54 exact policy comparisons and canonical sampled-path likelihoods. A branch verifier retains all positive-probability paths without truncation; raw state norms are checked and their floating-point normalization is recorded. This is numerical verification, not a theorem. No Lean formalization has been built for this driver.

The notebook provides bounded live controls in a local/Binder kernel. The static page requires no maintained server. Sampling is capped at 18 quantum wires; circuit construction has its own conservative operation guard. Branch enumeration has an immutable six-output-bit cap and a separate maximum-amplitude allocation. Unsupported quantum components are reported explicitly, even when their classical preliminary checks were supported.
