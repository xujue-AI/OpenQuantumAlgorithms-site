Classical recovery from an order-finding sample

Motivation and intuition¶

An order-finding measurement can encode a reduced fraction: its denominator may omit a common factor of the unknown order. Extra classical processing can recover that missing component without rerunning the quantum circuit. Ekerå’s analysis combines a nearby-frequency search with a small-prime-power search Ekerå, 2024. This page implements a bounded continued-fraction route and makes its classical work visible.

Executed scope and the small-instance limit

The implementation uses original integer-only code, freshly checked arithmetic circuits, identical samples for both recovery rules, and an additional bounded exact-order certificate. It has no true-order oracle or input-factorization routine. All default orders are small and fully smooth for the chosen bound. The retained classical shortcut can recover them before using the frequency; these examples demonstrate control flow and verification, not quantum advantage. Physical costing and formal correspondence remain pending.

Fundamental algorithm and important variants¶

Let aaa be coprime to NNN, with unknown order r<2mr<2^mr<2m, and let ttt be the number of measured phase bits. The implemented candidate route follows the paper’s continued-fraction method and Algorithms 3 and 4:

  1. Examine every distinct frequency j+u(mod2t)j+u\pmod{2^t}j+u(mod2t) for u=0,+1,−1,…,+B,−Bu=0,+1,-1,\ldots,+B,-Bu=0,+1,−1,…,+B,−B. There is no early peak-isolation heuristic.

  2. For each frequency, compute the last continued-fraction denominator qqq with q2<2tq^2<2^tq2<2t, using exact integer comparisons. Retain 1≤q<2m1\le q<2^m1≤q<2m.

  3. Set b=cmb=cmb=cm and E=∏p≤bp⌊log⁡pb⌋E=\prod_{p\le b}p^{\lfloor\log_p b\rfloor}E=∏p≤b​p⌊logp​b⌋ over primes ppp. The code constructs the powers by integer multiplication, avoiding rounded logarithms. Keep candidates with aEq≡1(modN)a^{Eq}\equiv1\pmod NaEq≡1(modN).

  4. Algorithm 3 uses a product tree to isolate each prime-power component of aqa^qaq, then finds its required exponent within the bound. Complete every retained candidate and choose the smallest returned period.

Here bbb-smooth means each entire prime power is at most bbb. An order component 16 is not 5-smooth, even though its only prime is two. The implementation also retains the paper’s useful shortcut: if aE=1a^E=1aE=1, apply Algorithm 3 to candidate one and recover the wholly smooth order classically.

For an optimal nearby frequency, the CF route requires t=m+lt=m+lt=m+l with 1≤l≤m1\le l\le m1≤l≤m and r2<2tr^2<2^tr2<2t. If its missing component is cmcmcm-smooth, the good candidate produces rrr. An arbitrary candidate can instead produce lcm⁡(r,q)\operatorname{lcm}(r,q)lcm(r,q), a proper multiple of the order. The implementation therefore distinguishes a verified period from an exact order. The lattice variants and the complete general success bound are external references, rather than implemented claims for every configured input Ekerå, 2024.

A separately charged exact-order certificate¶

For a returned period RRR, the bounded certificate completely factors RRR, checks aR=1(modN)a^R=1\pmod NaR=1(modN), and checks aR/p≠1(modN)a^{R/p}\ne1\pmod NaR/p=1(modN) for each distinct prime divisor ppp of RRR. These witnesses establish minimality as described in the paper’s correctness-verification section. Trial division is capped at R≤106R\le10^6R≤106; it factors the candidate period, not the input modulus. Larger periods remain labeled verified_period_only. This extra certificate does not make arbitrary large-period factorization efficient.

End-to-end resource analysis¶

For nnn input bits and ttt phase bits, the existing circuit has t+2n+2t+2n+2t+2n+2 logical wires and source work O(tn3+t2)O(tn^3+t^2)O(tn3+t2) with its exact-angle Fourier arithmetic. Both postprocessors retain the same complete 16-trial quantum workload here. The new recovery changes classical decisions and work; it does not remove any preparation, rotation, uncomputation or readout from those trials.

The CF loop records its divisions. At most 2B+12B+12B+1 shifted frequencies and that many distinct candidates are processed. The paper’s Algorithm 3 has total exponent-length scaling O(cmlog⁡(cm))O(cm\log(cm))O(cmlog(cm)) per candidate; this code records its actual modular-power calls, exponent lengths, sieve assignments and products. The additional period certificate can use O(R)O(\sqrt R)O(R​) integer divisions and separate modular witnesses. Those certificate costs are not part of the paper’s efficient smooth-completion bound.

Recorded CPU time and selected algorithm-operation counters are separate from physical quantum runtime; they are not CPython instruction counts or a portable CPU speed benchmark and do not count every Python multiplication. Input handling, classical readout/feedback communication and calibrated hardware latency still need an application model. A future equal-quality comparison may change the number of quantum trials, but it must first establish the new success contract, include every failed trial, and hold the physical assumptions fixed.

The surface-code baseline stays frozen. No new Native estimator or factory search ran. Existing physical reports have their own compiled traces and repetition contracts; this new classical comparison cannot inherit their runtime unchanged. Rotation synthesis, initialization, scheduling, factories, routing and classical-interface costing remain pending for this complete recovery policy. The logical counts and explicit exclusions are recorded.

Classical verification and available formalization¶

Independent integer checks compare the counted baseline with the book’s original rule on every frequency in bounded grids. They check optimal frequency/smoothness cases, false candidates that produce order multiples, prime-power failures, exact minimality witnesses and resource-limit outputs. The independent order-enumeration function is test-only; neither recovery API reads its answer or factors NNN.

The pinned Quaspy source is a MIT-licensed algorithm reference. We inspected its CF, filtering and Algorithm 3 routines, then wrote an integer-only implementation without importing the package or adding its dependencies. The exact upstream license is retained in the download. Qiskit, NumPy, SciPy and Matplotlib remain the locked upstream circuit/reference/rendering packages already credited by the main chapter.

No Lean or Coq proof has been built for this Python recovery implementation. The external Shor formalizations have different proved models; their theorem coverage is not a correspondence proof for these new functions or QASM exports.

Reproduce, scale and download¶

python scripts/generate_shor_recovery.py
pytest tests/test_shor_recovery.py tests/test_shor_recovery_artifacts.py

# A supplied large frequency invokes classical recovery without a simulator.
python scripts/generate_shor_recovery.py --modulus 59 --base 2 \
  --phase-bits 12 --outcome 70 --offset-radius 1 \
  --output-dir artifacts/recovery-59

The classical API permits up to 128 modulus bits, 256 phase bits, offset radius 32, cm≤512cm\le512cm≤512 and 8,192 modular-power calls per frequency, with an explicit resource-limit result. These are materialization/work guards, not large-instance performance evidence. Actual circuit simulation is independently capped at 18 wires and 4,096 outcomes; the default complete generation has a 180-second limit and a 64 MiB output cap. Custom/materialization-only runs use a separate output directory, preserving the default cohort.

The notebook replays the saved checks and executes the integer recovery examples. Optional local controls need a kernel; the static book uses saved outputs and needs no maintained server.
