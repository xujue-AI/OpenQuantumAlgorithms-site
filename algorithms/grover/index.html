Grover search

Motivation and intuition¶

Grover search amplifies the probability of a marked item using a reversible predicate and a reflection about a uniform superposition Grover, 1996. It is a useful first implementation because its circuit is small enough to inspect and its ideal success probability has a closed form. The survey gives the broader application and end-to-end complexity context Dalzell et al., 2025.

Note

Implementation status

The three-qubit demo is simulated and checked against the mathematical prediction during the site build. The generator supports other sizes. The exported circuit includes the oracle and diffuser decomposed into gates; the fixed three-qubit circuit compiles to exact Clifford and T operations, while larger circuits can require arbitrary-angle synthesis. The in-page surface-code baseline records the physical assumptions and estimator output.

Problem and input model¶

There are N=2nN=2^nN=2n computational basis states and exactly one marked state mmm. The phase oracle applies -1 to ∣m⟩\lvert m\rangle∣m⟩ and leaves every other basis state unchanged. Our explicit oracle compares the register to a known integer using X gates and a multi-controlled phase flip. This is a teaching example: knowing the target already solves the classical problem. A practical search application must replace it with a reversible problem predicate and count that predicate’s construction, evaluation, and uncomputation.

The notebook uses Qiskit core, an open-source circuit library released under Apache 2.0. The circuit generator is an original implementation using Qiskit core. See the upstream repository and the downloadable implementation source.

Fundamental algorithm and complexity¶

Prepare the uniform state with H⊗nH^{\otimes n}H⊗n. Repeat the phase oracle followed by reflection about that uniform state, then measure and verify the candidate. The two reflections rotate the state toward the marked subspace: the phase flip changes relative signs, and the diffuser converts that sign change into increased marked-state amplitude.

For one marked item among N=2nN=2^nN=2n, the first success peak uses Θ(N)\Theta(\sqrt N)Θ(N​) oracle calls Grover, 1996. Register width nnn and candidate count NNN are different size parameters. An oracle call is not a fixed gate cost: if its actual reversible construction costs CO(n)C_O(n)CO​(n) and diffusion costs CD(n)C_D(n)CD​(n), one trial costs preparation plus r[CO(n)+CD(n)]r[C_O(n)+C_D(n)]r[CO​(n)+CD​(n)] and readout. The equality oracle below has its own explicit decomposition; an application predicate requires a separate ledger.

Amplitude amplification generalizes the uniform input to a specified preparation circuit and success predicate. Its preparation inverse and reflections must be implemented and counted. This page implements the single-target Grover case; oblivious amplification in dynamics is a separate construction and task.

Important variants¶

Fixed-point amplitude amplification replaces fixed integer Grover rounds with a phase schedule chosen from a lower bound on initial success. The method page constructs the preparation inverse and both phase reflections, checks the promised success band, and records a bounded size/physical-cost sweep. The implemented threshold input has a simple classical answer; it is an access-and-accounting example.

Reversible SAT search¶

The SAT method constructs a reversible CNF predicate with clean conjunction work and full uncomputation. Its capped, count-agnostic search retains failed trials and verifies each measured assignment classically. The small circuits, larger generators and physical reports are separate from the known-target equality baseline. Physical replay covers fixed recorded prefixes; it does not certify an arbitrary adaptive search policy or an UNSAT result.

Small circuit: find 101¶

We prepare three qubits in the uniform superposition, mark integer 5 (bitstring 101), and apply two Grover iterations. Qiskit displays bitstrings with the most significant bit first; circuit wire q[0] represents the least significant bit.

Interactive exploration¶

Change the register size and iteration count in the browser explorer to inspect the ideal marked-state probability and the first success peak. This explorer evaluates the analytic formula. The saved figures above come from the Qiskit notebook.

Run the notebook in Binder for live Python controls that regenerate the actual Qiskit circuit and statevector. The controls support 2–6 qubits, an adaptive marked value, and 0–12 iterations. Every evaluation checks the simulated success probability against the closed form. The public notebook and its standalone implementation run independently of the private source repository.

The Binder recipe pins the scientific demo dependencies and uses Python 3.12. Its environment excludes the QDK resource estimator; physical estimates use the separate build environment and the surface-code baseline.

Run and generate other sizes¶

The downloadable notebook uses the same package implementation as the build script. To run the downloads independently, save grover.py beside grover.ipynb and install the scientific dependencies listed in the Binder environment. The generated metadata records the versions used by this build. From a source checkout, run:

python scripts/generate_grover.py
pytest tests/test_grover.py

# Approximately 0.9453125

To generate a larger register without simulating its exponentially large statevector:

python scripts/generate_grover.py --qubits 12 --marked 17 \
  --no-sim --no-scaling --output-dir artifacts/grover-12

Circuit generation and decomposition also consume time and memory; a large register does not imply an affordable classical simulation. The first Grover peak needs approximately πN/4\pi\sqrt{N}/4πN​/4 iterations, so even constructing a fully expanded circuit grows rapidly. For estimates beyond practical expansion sizes, an independently checked symbolic cost model is a separate deliverable.

Logical counts and physical resources¶

The generator transpiles the complete circuit into H, X, Z, S, T, their inverses, rotations, and CX. It records qubit width, depth, oracle calls, and the exact gate counts for the chosen Qiskit version and compilation settings. Every multi-controlled gate is decomposed before estimation. The OpenQASM 3 export contains decomposed gates and final measurements.

These logical counts are not physical qubit counts. A fault-tolerant estimate must specify rotation precision, logical error budget, code distance, state-distillation factories, timing, and failure probability. The surface-code baseline performs that handoff for this concrete circuit.

The scaling CSV covers 2–8 qubits with the all-ones target. It contains decomposed circuit counts rather than simulated large-register results. Changing the target changes which X gates are needed, and compilation choices can change gate counts.

End-to-end resource analysis¶

The first baseline estimates the circuit from this chapter: initialization, the explicit equality predicate, diffusion, and final measurements. It uses the open-source Microsoft Quantum Development Kit and its local qdk.qre estimator. The baseline is a gate-based rotated surface code with round-based magic-state factories.

These results describe an illustrative hardware model. They do not establish an application speedup or a measured hardware performance guarantee. The equality oracle tests a known three-bit string; an application predicate or database access would need its own implementation and cost.

Hardware and error assumptions¶

The two profiles use physical error rates of 10-3 and 10-4, 100 ns gate time, and 500 ns measurement time. These are editable model inputs, not benchmarks from a specific processor. The estimator explores the rotated surface-code and round-based factory model combinations and returns a Pareto frontier.

For the default example, one state is marked among eight and two Grover iterations are used. The ideal success probability per circuit execution is

psuccess=sin⁡2 ⁣(5arcsin⁡(1/8))=0.9453125.p_{\mathrm{success}} = \sin^2\!\left(5\arcsin(1/\sqrt{8})\right) = 0.9453125.psuccess​=sin2(5arcsin(1/8​))=0.9453125.
(3)

We set an overall failure target of 1%, reserve 0.5% for sampling failure and 0.5% for physical faults, and run two trials serially. Ideal sampling failure is (1−psuccess)2≈0.002991(1-p_{\mathrm{success}})^2\approx0.002991(1−psuccess​)2≈0.002991. Each trial receives a physical-failure allowance of 0.25%. A union bound gives overall failure at most 0.7991% under the declared model and ideal verification assumptions. The report records the tighter bound from each returned estimate.

Peak physical qubits remain the per-trial peak because trials run serially. Runtime is multiplied by two. Quantum measurement time is included; classical verification and circuit compilation time are currently unmeasured and excluded. An application with input loading or a more complex predicate must extend this boundary before its estimate can be called end to end.

Reproduce and inspect¶

In a project checkout:

python scripts/generate_grover.py
python scripts/estimate_resources.py

To reproduce using only public downloads, save the OpenQASM circuit, matching circuit metadata, estimation script, and locked Python dependencies in one directory. In a Python 3.12 environment, run:

python -m pip install -r requirements-lock.txt
python estimate_resources.py --qasm circuit.qasm \
  --logical-metadata logical-resources.json \
  --output-dir resource-results --cache-dir estimator-cache

The estimator consumes the fully decomposed OpenQASM 3 file and records its SHA-256 digest. It rejects missing measurements and remaining custom gate declarations. Changing the qubit count or iteration count requires generating a matching circuit and passing matching --n-qubits, --marked, and --iterations arguments to the estimator. Package versions are embedded in the report.

The baseline uses the documented local estimator installation, OpenQASM application interface, QEC and factory models, and result quantities and provenance. EstimationTableEntry.runtime is reported in nanoseconds and converted to milliseconds on this page.

Verification and formalization¶

The tests verify that the oracle flips exactly the requested basis state, that simulated success matches the closed form for several register sizes and iteration counts, and that decomposition preserves the unitary up to global phase. These are numerical and functional checks.

Formal proof coverage is not yet integrated. The SQIR/VOQC project provides relevant quantum algorithm proofs in Coq/Rocq; a linked proof does not establish correctness of this Python generator or its surface-code compilation. Any later proof badge must record the theorem, assumptions, pinned proof toolchain, successful proof build, and connection to this circuit.

Status: small circuit and resource contracts checked; no integrated formal proof. The implementation uses an explicit equality phase oracle, whose marked integer is known to the generator. This is a teaching instance for circuit correctness.

What is checked¶

The 22 dedicated Grover test cases cover oracle signs on computational basis states, invalid inputs, bit ordering, ideal success probabilities, and decomposition into the supported logical basis. Oracle matrices are compared with an independently specified diagonal matrix. Simulation results are compared with

P(m)=sin⁡2 ⁣((2r+1)arcsin⁡(1/2n)).P(m)=\sin^2\!\left((2r+1)\arcsin(1/\sqrt{2^n})\right).P(m)=sin2((2r+1)arcsin(1/2n​)).
(4)

The three-qubit case with target 101 and two iterations has ideal probability 121/128=0.9453125121/128=0.9453125121/128=0.9453125. The compiled circuit is compared with the original unitary up to global phase. These are numerical checks over the tested instances, not a proof for every register size.

The notebook also checks 30 bounded cases for its live controls. Every interactive evaluation verifies the simulated marked-state probability against the same analytic expression. Saved circuit and probability outputs are reused in the chapter; a static page does not execute the Python controls.

What resource checks establish¶

The 13 baseline-contract test cases check repetition arithmetic, allocation between ideal sampling failure and modeled physical faults, and rejection of opaque or unmeasured inputs. The frozen resource report records the actual circuit digest and assumptions.

The seven general-resource-helper cases separately check static lowering, budget semantics, rejected operations, and the audited arbitrary-rotation model. That helper’s mean-fit projections are conditional and do not certify concrete synthesis sequences. Its tests do not expand the proof scope of the frozen Grover instance.

Remaining evidence¶

A practical search predicate needs its own reversible implementation, independent semantic checks, loading cost, and classical verification procedure. An integrated theorem would need to identify its mathematical object, assumptions, toolchain, and connection to this Python circuit. External SQIR/VOQC proofs are relevant references; this project has not reproduced a proof that covers the implementation and its physical compilation.

See fault-tolerance background for the distinction between circuit accuracy, sampling confidence, and modeled physical reliability.
